# 五轨说明

本站把文献分成五条轨道。轨道不是"主题罗列"，而是按**这项研究在回答什么问题**分层。这份文档说明判定规则、边界判例，以及怎么维护。

轨道的定义在 `industry/taxonomy.ts` 的 `CATEGORIES`，判定提示词在 `industry/prompts/structure.md`。**key 已经进了网址**（`/all?category=…`、`/feed/category/*.xml`、公开 API 的 `category` 参数），上线后不要再改。

| 轨道 | key | 回答的问题 |
|---|---|---|
| 共生菌与微生物组 | `symbiont` | 菌能不能用来阻断传播？怎么用？ |
| 传播效能与媒介 | `transmission` | 这群蚊能不能传病？传得多容易？ |
| 预测与建模 | `prediction` | 接下来会怎样？风险在哪？ |
| 病毒与疾病 | `virus-disease` | 病原怎么致病？怎么识别？ |
| 防控与政策 | `control-policy` | 措施有没有效？该不该推广？ |

## 判定顺序

`structure.md` 里是一个五问决策树，**必须按顺序问，第一个答"是"的就是主轨，后面的不再问**：

```
问 1  主要产出是一个模型 / 预测 / 风险量化吗？
      （有训练或拟合、有验证或外推、结果是对未观测情形的推断）
      → 是：prediction，到此为止

问 2  被操作或被测量的是菌、菌群、内共生菌吗？
      → 是：symbiont

问 3  被测量的是蚊的传递能力或媒介性状吗？
      （感染率、播散率、唾液腺感染、外潜伏期、病毒载量、媒介能力、
        血餐偏好、寿命、适应性代价、行为、种群动态、杀虫剂抗性）
      → 是：transmission

问 4  被研究的是病毒本身或病人吗？
      （病毒学、致病与免疫、临床特征、诊断、血清学、暴发、疾病负担）
      → 是：virus-disease

问 5  被评估的是一项公共卫生措施吗？
      （疫苗、抗病毒、杀虫剂应用、蚊帐、社区干预、指南政策、卫生经济）
      → 是：control-policy

五问都不成立 → category 给 null，不猜
```

### 为什么问 1 必须放最前

气象数据加病例数再加机器学习，这类论文全文可能一只蚊子都没有，但它确实属于"预测"。如果先问"被测量的对象是什么"，它会答"病例数"，然后一路滑到 `virus-disease`。

更要命的是，模型类论文对其他问题几乎都会答"是"——它可能同时涉及病毒、蚊虫和防控措施。所以问 1 必须能**截断**，不能当作并列条件之一。

### 为什么综述不等于模型

系统评价、Meta 分析即使主题是模型或算法，也**不成立问 1**。它们的主要产出是综合既有证据，不是新的推断。按被综合的主题归轨：AI 辅助诊断的系统评价 → `virus-disease`；媒介能力的 Meta → `transmission`。

这条规则是实测补上的：早期版本让一篇「AI 用于蚊媒病毒早期诊断的系统评价」落进了 `prediction`，因为它通篇在讲算法。

## 三组最容易判错的边界

### ① 共生菌 vs 传播效能

**看有没有对菌的处理或测量。**

| 材料 | 主轨 | 理由 |
|---|---|---|
| 转染 wMel 后测埃及伊蚊对 DENV 的传播阻断 | `symbiont` | 被操作的是菌 |
| 不带菌的两株伊蚊对 DENV 的感染率差异 | `transmission` | 无菌处理，测的是蚊的传递能力 |
| Wolbachia 论文里顺带测了外潜伏期 | `symbiont` | 副标打「外潜伏期」，不改主轨 |

### ② 传播效能 vs 预测

**看主要贡献落在哪。**

| 材料 | 主轨 | 理由 |
|---|---|---|
| 实测某蚊种对 CHIKV 的感染率与播散率 | `transmission` | 贡献是新参数 |
| 用文献参数算某地 DENV 的 R0 | `prediction` | 贡献是模型 |
| 既测参数又建模型，参数是新的 | `transmission` | 新数据 > 标准模型 |
| 既测参数又建模型，模型是新的 | `prediction` | 新方法 > 补充数据 |

### ③ 预测 vs 病毒与疾病

**看产出是工具还是观察。**

| 材料 | 主轨 | 理由 |
|---|---|---|
| 登革重症预测评分（列线图、机器学习分类器） | `prediction` | 产出是预测工具，需要外部验证 |
| 登革重症的临床特征与危险因素描述 | `virus-disease` | 产出是观察结果 |
| DENV 蛋白结构预测与抑制剂虚拟筛选 | `prediction` | 产出是计算推断，需湿实验验证 |

注意："severity prediction""risk score""prognostic model"这些词本身不算证据，要看有没有真的建模和验证。

## 跨轨关联

一篇论文只归一条主轨，但**其他轨道的主题照常打标签**。这是跨轨阅读的唯一依据。

例如一篇归入 `symbiont` 的论文，如果测了感染率与传播率，必须打「媒介能力」「感染率」——这样它在 `transmission` 轨的关联条带里能被找到。

标签词表在 `industry/taxonomy.ts` 的 `TOPIC_TAGS`，分七簇：菌 / 病原 / 传播效能 / 预测建模 / 干预 / 蚊种与阶段 / 地域。加标签前先想清楚它属于哪一簇，一个标签只在最直接描述它的那簇出现。

## 后台兜底

判轨由模型在 `structure` 步骤完成，会有误判。后台「内容诊断」可以逐条人工改判，改过的记录不会被后续流程覆盖。

如果某一批材料系统性判错，改 `structure.md` 的判例，**不要改代码**。注意提示词版本是内容哈希：改了提示词只影响新条目，已判过的不会自动重算，需要清库重跑或后台逐条改判。

## 怎么加一条轨道

1. 在 `CATEGORIES` 加一项，key 全小写加连字符（会进网址，定了别改）
2. 给 `guide`——写明这一轨收什么、和相邻轨的边界在哪（拼进提示词）
3. 在 `structure.md` 的决策树里插入对应的问题，**并检查它该排在第几问**
4. 在 `topics.json` 加对应主题（可选，也可以只做标签）
5. 如果新轨需要独立采集线，加一份 `config/<name>.json` 并在 `push_to_site.py` 的 `LINES` 里登记
6. 清库重跑存量，核对每轨的判例是否还成立

加轨**不需要数据库迁移**：`publications.category` 是自由文本，没有 CHECK 约束，前端筛选栏和分类 RSS 都从 `CATEGORIES` 自动生成。
